# AI-generated Presets

A Preset — a Theme plus starting Page layouts — can be generated by a model and chosen
from a handful of options, rather than authored by hand for every new Site. This is
deliberately narrower than the Page generation excluded in
[ADR-0006](./0006-v1-scope-boundary.md), and the narrowing is what makes it safe: a Preset
is produced at creation time, not during editing, so nothing is generated on a live Page,
and its output is Block JSON validated against the Zod schemas from
[ADR-0004](./0004-page-layout-as-a-single-json-document.md). A model cannot invent a Block
Type that does not exist; invalid output is rejected before it is ever stored.

The generator produces the Theme and the Pages together. Generated separately they are
incoherent — a considered palette on a generic layout — and most of a Site's apparent
uniqueness comes from the Theme rather than the arrangement of Blocks.

## Decisions

- **Provider-agnostic, with a default.** Generation goes through a provider abstraction so
  a Site can be pointed at a different vendor when a client insists. The default is
  Anthropic's `claude-opus-5`. Model selection is an Owner-only Site setting, never a
  per-request choice, and never visible to an Author.
- **Each Site holds its own API key.** Sites share nothing at runtime
  ([ADR-0001](./0001-packaged-template-cloned-per-site.md)); a shared key would be the one
  exception, and one Site's runaway usage would throttle every other client.
- **Owners apply Presets to a new Site. Authors may apply one to a single Page.** An
  Author's application writes to that Page's Draft and snapshots the previous version
  first, so regenerating a page a client dislikes is an undo, not an incident. An Author
  can never apply a Preset across a whole Site, and never to Published content directly.

## Consequences

- Generated output is only as varied as the Block library. With a handful of Block Types
  every Preset looks like the same Site in different colours, which is why this is
  sequenced after the library has grown.
- The Zod schemas become load-bearing in a new way: they are now the validation boundary
  for untrusted model output, not only for the Editor's own writes.
